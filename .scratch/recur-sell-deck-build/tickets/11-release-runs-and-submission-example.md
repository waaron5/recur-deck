# 11: Release runs and submission example

**What to build:** The decision to ship, made on evidence. The release set — US Fleet Tracking, Lattice, Shopmonkey, Pool Office Manager, Dockwa, and Luma Health — is run on the final ZIP, each once, in a fresh chat, with the company name typed the way someone at Recur would type it and no URL. Each company carries one hard case, so a failure points at one cause: an ambiguous name, a small-town headquarters, a thin competitor field, a blocked site, and one clean control.

Every run is judged in real PowerPoint against the critical-defect list, with facts and competitor choices spot-checked against the run's speaker notes. Zero critical defects across all six, each under fifteen minutes, is the bar. A failed run means fixing the workflow and rerunning the whole set on the new ZIP; results are only ever reported for the final ZIP. If a company has left the covered scope, the next reserve candidate takes its slot and the tested-on table discloses the swap. A reserve never stands in for a failed run.

Three behavior checks run alongside and count toward nothing: one run with the domain allowlist at its default, expecting a fast evidence failure with the allowlist fix; one public software company, expecting a deck plus the outside-the-covered-scope line; and the ambiguous name with its URL in the prompt, only if the bare-name run picked the wrong company.

The submission example is the untouched US Fleet Tracking file from a run on the final ZIP, free of critical defects and of quality notes. If that run has a quality note, up to two more US Fleet Tracking runs are allowed on the same ZIP, and every one of them counts in the reported tally. The file is never hand-edited.

Finally the guide's tested-on table is filled in — company, sector, hard case, time, fallbacks, result — along with the precise results sentence, and the package, guide, and example deck are ready to hand over.
