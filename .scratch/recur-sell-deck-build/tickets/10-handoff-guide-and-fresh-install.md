# 10: Handoff guide and fresh-user install check

**What to build:** Someone at Recur who has never seen this before can read one page, set up their account, and get a deck. The guide is a single page as a PDF, with the same text usable in the email body, and it reads clean, simple, and impressive: what's included; the four setup steps including setting the domain allowlist to all domains with a one-line security note; how to run it, with the prompt, the tip that adding the company's URL settles which company is meant, a typical time of about ten minutes, web search on, and the tested model; what you might see, covering a clean deck, the fallbacks line, a NOT READY deck, and an evidence failure with its fix; where the sources are, in the speaker notes of slides 1–3; a tested-on table; and the known soft spots — the print softness of slides 4–9, text wordmarks used on purpose rather than as defects, the landmark fallback rungs, and what the covered-target scope does and does not promise. It leaves out how the workflow was built; that is for the meeting.

Then the guide is tested the only way that counts: one install done from the guide alone, ideally by a second person on their own account, otherwise on a fresh account. It is timed against the ten-minute setup target and every step the guide missed or got wrong is fixed. That run's deck is informational only.

The tested-on table and the precise results sentence are left blank here; ticket 11 fills them from the release runs.
